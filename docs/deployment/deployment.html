TokenRadar Deployment Architecture

This repo deploys through GitHub Actions and publishes a Next.js static export to Cloudflare Pages. The site does not use a Next.js server runtime in production.

There is one scoped Cloudflare Pages Function in advanced mode: public/_worker.js returns 410 Gone for retired /compare URLs, and public/_routes.json limits that function to /compare and /compare/*. Normal page and asset traffic remains static Pages traffic.

Deployment Overview

The deployment path is GitHub-driven:

  1. GitHub Actions builds the site artifact.
  2. npm run build creates the static out/ directory.
  3. The deploy workflow verifies out/ and the Pages file budget.
  4. Wrangler uploads out/ to the Cloudflare Pages project.
  5. Cloudflare Pages serves the uploaded artifact.

Cloudflare Pages dashboard build settings are informational for this repo. The source build does not run inside Cloudflare Pages.

Data and Content Pipelines

Authored data generation happens in GitHub Actions and local scripts, not at request time.

The daily refresh workflow refreshes market and support data before redeploying when committed artifacts change. Its main responsibilities include:

  • scripts/fetch-crypto-data.ts: refresh token market data
  • scripts/discover-tges.ts: refresh upcoming TGE candidates in data/upcoming-tges.json
  • scripts/fetch-reference-articles.ts: refresh supporting references
  • scripts/compute-metrics.ts: compute derived TokenRadar metrics
  • scripts/refresh-meta-tokens.ts: rotate Meta access tokens used by social workflows
  • scripts/generate-og-images.tsx --force: regenerate static OG images
  • scripts/consolidate-data.ts, scripts/validate-content.ts, and scripts/generate-sitemap.ts: validate and prepare runtime artifacts

The daily content workflow generates and publishes queued article payloads. Its main responsibilities include:

  • scripts/generate-content.ts --queue: generate queued article JSON
  • scripts/quality-check.ts --dir data/queue --fix --delete-failures: gate queued content quality
  • scripts/publish-from-queue.ts: inject live placeholders and move finished content into content/tokens/
  • scripts/inject-internal-links.ts: add semantic internal links
  • scripts/repair-article-content.ts: normalize published article formatting
  • scripts/validate-content.ts: validate published content before commit
  • npm run build: run a build gate before publishing generated content to main

Generated artifacts are committed back into repository paths such as:

  • data/tokens/
  • data/prices/
  • data/metrics/
  • data/references/
  • data/upcoming-tges.json
  • data/_tokens_blob.json, data/_metrics_blob.json, data/_prices_blob.json, and data/_registry.json
  • content/tokens/
  • public/og/movers.png
  • public/sitemap.xml, public/sitemap-main.xml, and public/sitemap-tokens.xml

Build and Deploy Workflow

Deployment is handled by .github/workflows/deploy.yml.

That workflow can run from a push to main, a manual dispatch, or a reusable workflow call from another workflow.

The deploy job:

  1. Validates the requested deploy ref for non-push events.
  2. Checks out the requested ref.
  3. Installs dependencies with npm ci.
  4. Restores the Next.js build cache.
  5. Runs npx tsc --noEmit.
  6. Runs npm run lint.
  7. Runs npm run test.
  8. Runs npm run build with production public site variables.
  9. Verifies out/ exists.
  10. Runs npm run deploy:check-files.
  11. Uploads out/ to Cloudflare Pages with wrangler pages deploy.
  12. Pings IndexNow when INDEXNOW_KEY is configured.
  13. Uploads deploy diagnostics on failure.
  14. Sends a Telegram failure notification when reporting secrets are configured.

Manual deploys are restricted to main. Reusable workflow calls may deploy a full commit SHA only when allow_sha_ref is true. The daily content workflow uses this SHA path to deploy the exact generated-content commit.

Prebuild Chain

npm run build triggers npm run prebuild first.

The current prebuild sequence is:

  1. scripts/validate-env.ts
  2. scripts/compute-search-intent.ts
  3. scripts/consolidate-data.ts
  4. scripts/validate-content.ts
  5. scripts/generate-og-images.tsx
  6. scripts/generate-sitemap.ts

This keeps the exported site consistent with authored content and consolidated data blobs before Next.js renders pages.

Cloudflare Pages Runtime Shape

next.config.ts uses output: "export" and disables Next image optimization with images.unoptimized.

Most requests are served as static Cloudflare Pages assets. Security headers, cache rules, and CSP are defined in public/_headers and become part of the uploaded Pages artifact.

The exception is the retired /compare route family:

  • public/_worker.js is a Pages Function in advanced mode.
  • public/_routes.json includes only /compare and /compare/*.
  • Requests to those paths return 410 Gone with security headers.
  • All other requests should bypass the function and remain static asset requests.

Because Pages Functions count against the Workers Free plan quota, keep _routes.json narrow. Do not change it to /* unless the site is intentionally moving from static Pages serving to Worker-invoked serving. As of this review on 2026-05-18, Cloudflare documents a Workers Free quota of 100,000 requests per day for Worker and Pages Function invocations.

Static Export Constraints

Static export means:

  • no Next.js runtime server is required
  • pages must be build-time compatible
  • image optimization is disabled in Next and handled as plain static assets
  • authored routes must avoid runtime-only APIs
  • dynamic edge behavior should stay explicitly scoped through Pages Functions routing

Environment and Secrets Checklist

The deploy workflow requires:

  • CLOUDFLARE_API_TOKEN
  • CLOUDFLARE_ACCOUNT_ID

The production build reads public GitHub Actions variables such as:

  • SITE_URL or the default https://tokenradar.co
  • SITE_NAME or the default TokenRadar
  • NEXT_PUBLIC_GA_MEASUREMENT_ID
  • NEXT_PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN

Optional deploy follow-up and alerting use:

  • INDEXNOW_KEY
  • TELEGRAM_REPORT_BOT_TOKEN
  • TELEGRAM_REPORT_CHAT_ID

Data and content workflows also depend on provider credentials such as COINGECKO_API_KEY, GEMINI_API_KEY, ANTHROPIC_API_KEY, Meta tokens, and GA4/GSC credentials. Keep .env.example and GitHub Actions secrets aligned when adding or removing workflow steps.

Free-Tier Guardrails

  • npm run deploy:check-files fails before Cloudflare Pages reaches the configured static file budget.
  • Keep the Pages Function route list limited to retired /compare URLs so normal static traffic does not consume Workers Free quota.
  • Cloudflare Web Analytics should use either dashboard injection or NEXT_PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN, not both.
  • R2 staging objects should stay short-lived: successful social publishes delete exact keys, npm run r2:cleanup-ledger removes expired tracked failures, and bucket lifecycle rules should expire video/ and ig-carousel/ after 1-2 days.
  • Deploy, data refresh, content generation, social automation, performance, dependency-security, video-asset refresh, and monthly snapshot workflows all upload short-retention diagnostics instead of committing transient logs.

Operational Notes

  • The deploy workflow currently uses Node 22.
  • Daily refresh and daily content generation currently use Node 20.
  • The git-push-main concurrency group serializes workflows that commit generated artifacts to main.
  • If a generated-data workflow aborts because origin/main changed during the run, rerun the workflow on the latest main rather than auto-merging generated output.
  • Rollbacks should be handled by reverting or fixing main and redeploying through the workflow, unless a trusted reusable workflow caller intentionally deploys a specific full commit SHA.
