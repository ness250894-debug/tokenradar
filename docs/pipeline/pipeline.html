TokenRadar Content Pipeline

This generated artifact pair is the source of record for how data, content, build artifacts, deployment, and social automation move through the repository. The retired root PIPELINE.md source has been removed; keep docs/pipeline/pipeline.json and docs/pipeline/pipeline.html updated together.

1. Workflow Boundaries

The pipeline is split across scheduled GitHub Actions and local scripts.

  • Daily refresh: .github/workflows/daily-refresh.yml refreshes market data, TGE candidates, reference snippets, metrics, Meta tokens, OG images, consolidated blobs, content validation, sitemap artifacts, analytics baseline, system report, and deploys when committed artifacts change.
  • Daily content generation: .github/workflows/daily-content-generation.yml runs Smart Drip article generation, gates queued drafts, publishes a bounded batch with live data, repairs and validates content, runs a build gate, commits approved content, and calls deploy for the exact commit SHA.
  • Deploy: .github/workflows/deploy.yml typechecks, lints, tests, builds the static export, verifies out/, checks Cloudflare Pages file budget, deploys with Wrangler, and pings IndexNow when configured.
  • Social automations: .github/workflows/social-automations.yml is separate from website publication but consumes the same data/content base and must follow editorial constraints.
  • Video asset refresh: .github/workflows/video-assets-refresh.yml maintains persistent b-roll assets used by short-form social video.

2. Discovery and Data Refresh

  • scripts/fetch-crypto-data.ts: refreshes CoinGecko token data, per-token detail files, price histories, and token registry inputs.
  • scripts/discover-tges.ts: refreshes upcoming TGE candidates in data/upcoming-tges.json.
  • scripts/agent-narrative-hunter.ts: experimental narrative scouting and optional discovery support.
  • scripts/fetch-reference-articles.ts: refreshes supporting reference snippets used during generation.
  • scripts/compute-metrics.ts: computes derived TokenRadar metrics in data/metrics/.
  • scripts/refresh-meta-tokens.ts: rotates Meta access tokens used later by social workflows.
  • scripts/export-engagement-baseline.ts and scripts/send-system-report.ts: run as best-effort daily refresh follow-ups for analytics and operational reporting.

3. Content Generation Queue

  • scripts/generate-content.ts --drip --queue: writes drafts into data/queue/.
  • Smart Drip priority is TGE previews, newly released TGE graduates, volatile tokens, incomplete content hubs, then stale published articles.
  • Daily workflow controls are CONTENT_MAX_REFRESH, CONTENT_MAX_TGE, and CONTENT_PUBLISH_MAX.
  • Generated articles use token data, price history, TokenRadar metrics, TGE records, and reference snippets.
  • scripts/keyword-generator.ts: refreshes data/keywords.json for SEO support; it is not currently scheduled in the main daily workflows.

4. Queue Quality Gate

  • scripts/quality-check.ts --dir data/queue --fix --delete-failures: applies blocking checks and limited fixes in the daily content workflow.
  • Automated daily queue failures are deleted from data/queue/, not quarantined.
  • Manual/local review can use --quarantine to move failures under data/quarantine/; do not describe this as the automated default.
  • Blocking issues include missing required structure, low word count, prohibited promotional/advice language, malformed content, unapproved outbound URLs, and unresolved live placeholders.

5. Publication and Post-Processing

  • scripts/publish-from-queue.ts --max: injects live placeholders and writes approved files into content/tokens/.
  • Publish-time unresolved placeholders or failed quality snapshots are blockers; queue files can be removed during this step.
  • Pre-launch TGE articles may publish with explicit TBA market fields when no live pool exists.
  • scripts/inject-internal-links.ts: adds glossary and semantic internal links to published content.
  • scripts/repair-article-content.ts: normalizes published article formatting and updates quality snapshots in the automated workflow.
  • scripts/fix-article-formatting.ts and scripts/repair-tge-content.ts: retained manual/legacy repair helpers, not the current scheduled post-processing path.
  • scripts/validate-content.ts: validates the authored content surface before commit, build, and deploy.

6. Runtime Artifact Chain

npm run build triggers npm run prebuild; the prebuild chain is part of the publication flow.

  • scripts/validate-env.ts: checks build-critical environment.
  • scripts/compute-search-intent.ts: generates data/search-intent.json and data/search-intent-history.json from cached token data, metrics, keyword templates, and TGE records.
  • scripts/consolidate-data.ts: builds consolidated static/runtime blobs such as data/_tokens_blob.json, data/_metrics_blob.json, data/_prices_blob.json, and data/_registry.json.
  • scripts/validate-content.ts: re-runs content validation before static rendering.
  • scripts/generate-og-images.tsx: refreshes static OG images, including token and movers artwork.
  • scripts/generate-sitemap.ts: writes sitemap artifacts into public/.

7. Build and Delivery

  • Daily refresh commits generated data artifacts only when tracked outputs change, then calls the deploy workflow.
  • Daily content generation commits approved content artifacts only when publication changes content, then calls deploy with the generated commit SHA.
  • The deploy workflow runs npx tsc --noEmit, npm run lint, npm run test, npm run build, output verification, and npm run deploy:check-files.
  • Cloudflare Pages receives the static out/ artifact through wrangler pages deploy.
  • scripts/ping-indexnow.ts runs after deploy and is best-effort when INDEXNOW_KEY is configured.
  • git-push-main concurrency serializes generated commits to main; if origin/main changes mid-run, rerun instead of auto-merging generated output.

8. Failure Handling and Diagnostics

  • Daily refresh, content generation, deploy, social automation, performance, dependency-security, video-asset refresh, and monthly snapshot workflows upload short-retention diagnostics on failure.
  • Telegram failure notifications are best-effort and skipped when report secrets are missing.
  • Failed queue files may be deleted by automated queue gates, moved to quarantine only in manual/local review, or left in place in check-only mode.
  • Published-content failures should be fixed forward when narrow; broad risk can require reverting or removing the page and redeploying.
  • Live data hydration failures block normal token publication, except explicitly marked pre-launch TGE cases.

9. Social Distribution Boundary

The social layer consumes the same market/content base but is not the website publication pipeline.

  • Website-adjacent social scripts: scripts/post-market-updates.ts, scripts/post-interactive-daily.ts, scripts/post-daily-poll.ts, scripts/post-daily-movers.ts, scripts/post-instagram-daily-movers.ts, scripts/post-threads-daily.ts, and scripts/post-video-daily.ts.
  • Social operations also use scripts/d1-migrate.ts, scripts/record-automation-run.ts, scripts/backfill-social-ledger.ts, scripts/snapshot-cloudflare-usage.ts, scripts/cleanup-r2-staging.ts, scripts/d1-smoke.ts, and scripts/report-ops-ledger.ts.
  • Short-form video depends on scripts/sync-video-assets-from-r2.ts, scripts/fetch-video-assets.ts, scripts/generate-blender-assets.ts, and scripts/sync-video-assets-to-r2.ts.
  • Social copy, captions, polls, and video scripts inherit editorial no-advice/no-hype rules even when they do not publish website pages.

10. Coverage Notes

  • docs/editorial/ defines editorial gates and manual review rules.
  • docs/deployment/ covers Cloudflare Pages build/deploy architecture.
  • docs/integrations/ covers external services, secrets, scheduled automation, D1, R2, and platform failure paths.
  • docs/data-schema/ covers JSON contracts and producer/consumer data movement.
  • Keep this pipeline doc focused on flow order, handoffs, blockers, and which scripts are scheduled versus manual.
