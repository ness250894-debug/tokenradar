TokenRadar Integrations & Environment

This reference catalogs the external services, credentials, scheduled workflows, and failure paths used by TokenRadar. The root INTEGRATIONS.md source has been retired; keep docs/integrations/integrations.json and docs/integrations/integrations.html updated together.

1. End-to-End Automation Flow

Flow Trigger Core scripts Integration handoff
Daily refresh .github/workflows/daily-refresh.yml at 17:45 UTC and manual dispatch fetch-crypto-data.ts, discover-tges.ts, fetch-reference-articles.ts, compute-metrics.ts, refresh-meta-tokens.ts, generate-og-images.tsx, send-system-report.ts Refreshes market data, TGE data, reference summaries, Meta tokens, OG images, analytics baselines, then redeploys only when tracked data changes.
Daily content generation .github/workflows/daily-content-generation.yml at 06:00 UTC and manual dispatch generate-content.ts, quality-check.ts, publish-from-queue.ts, inject-internal-links.ts, repair-article-content.ts, validate-content.ts Generates queued content, applies quality gates, publishes a bounded batch, validates the static build, commits content, and calls the deploy workflow.
Social automations .github/workflows/social-automations.yml scheduled slots and manual routing post-market-updates.ts, post-interactive-daily.ts, post-daily-poll.ts, post-daily-movers.ts, post-threads-daily.ts, post-video-daily.ts Routes posts to Telegram, X, Instagram, Threads, YouTube, and TikTok. It also records D1 ops data, cleans R2 staging, persists rotated OAuth secrets, and sends failure alerts.
Video asset refresh .github/workflows/video-assets-refresh.yml weekly and manual dispatch sync-video-assets-from-r2.ts, fetch-video-assets.ts, generate-blender-assets.ts, sync-video-assets-to-r2.ts Hydrates the b-roll manifest, fetches provider clips, optionally generates Blender loops, and publishes persistent video assets to R2.
Deploy .github/workflows/deploy.yml on push, manual dispatch, and workflow calls validate-env.ts, compute-search-intent.ts, consolidate-data.ts, validate-content.ts, generate-og-images.tsx, generate-sitemap.ts, ping-indexnow.ts Typechecks, lints, tests, builds the static export, deploys to Cloudflare Pages, and pings IndexNow.
Performance .github/workflows/performance.yml on PRs, weekly, and manual dispatch pagespeed-snapshot.ts, Lighthouse CI Runs local performance gates for PRs and PageSpeed snapshots for live site checks when API credentials exist.
Monthly snapshot .github/workflows/monthly-data-snapshot.yml monthly and manual dispatch shell archive plus gh release create Archives public data, content, and media into a monthly GitHub release. Runtime caches and social cooldown state are excluded.

2. Data Providers

CoinGecko & GeckoTerminal

  • Purpose: primary token pricing, market cap, supply, rank, volume, and DEX liquidity data.
  • Scripts: scripts/fetch-crypto-data.ts, src/lib/coingecko.ts, and downstream content/social scripts.
  • Rate-limit handling: request delays, cache-first reads, and fetchWithRetry() for retryable failures.
  • Required secret: COINGECKO_API_KEY for authenticated quota.

Reference Articles and Reddit

  • Purpose: external context for content generation and market narratives.
  • Script: scripts/fetch-reference-articles.ts.
  • Optional secrets: REDDIT_CLIENT_ID, REDDIT_CLIENT_SECRET enable Reddit API enrichment when present.
  • Failure mode: reference fetching can run without Reddit credentials; the rest of the refresh flow continues.

3. Artificial Intelligence

Google Gemini Primary

  • Purpose: primary generation engine for articles, market updates, social copy, polls, and short-form video narration.
  • Model: gemini-2.5-flash through src/lib/gemini.ts.
  • Required secret: GEMINI_API_KEY.

Anthropic Claude Fallback

  • Purpose: fallback model in callAIWithFallback() when Gemini returns rate-limit or overload errors.
  • Model: claude-haiku-4.5 unless the calling script overrides it.
  • Required secret: ANTHROPIC_API_KEY.
  • Failure mode: if both providers fail, content/social scripts should surface the error to logs and Telegram reporting where configured.

4. Social Distribution & Publishing

X Twitter

  • Purpose: market updates, interactive polls, video/link replies, and trend lookups.
  • Auth flow: OAuth 2.0 PKCE with rotating refresh tokens from scripts/generate-x-token.ts and src/lib/x-client.ts.
  • Required secrets: X_OAUTH2_CLIENT_ID, X_OAUTH2_CLIENT_SECRET, X_OAUTH2_REFRESH_TOKEN.
  • Additional secret: X_BEARER_TOKEN is required for app-only trend endpoints.
  • Rotation persistence: src/lib/x-client.ts writes NEW_X_REFRESH_TOKEN to GITHUB_ENV; social-automations.yml persists it back to GitHub Secrets with GH_PAT.
  • Fallback behavior: native poll failures can fall back to text-based poll posts.

Meta Instagram & Threads

  • Purpose: Instagram carousel/Reels and Threads posts via the Meta Graph API.
  • Flow: media containers are created first, then published after the container reaches a ready status.
  • Required secrets: IG_ACCESS_TOKEN, IG_ACCOUNT_ID, THREADS_ACCESS_TOKEN, THREADS_ACCOUNT_ID.
  • Rotation secrets: META_APP_ID, META_APP_SECRET, and GH_PAT allow scripts/refresh-meta-tokens.ts and social automation steps to persist refreshed access tokens.
  • Storage dependency: Meta media creation needs public media URLs, supplied by the R2 staging bucket.
  • Failure mode: invalid token errors require refresh or manual re-auth; failed-run media remains briefly for diagnostics and lifecycle cleanup.

Telegram

  • Purpose: public channel broadcasts plus private operational reports.
  • Required broadcast secrets: TELEGRAM_BOT_TOKEN, TELEGRAM_CHANNEL_ID.
  • Required reporting secrets: TELEGRAM_REPORT_BOT_TOKEN, TELEGRAM_REPORT_CHAT_ID.
  • Failure mode: workflows skip failure notifications when reporting secrets are absent; publishing scripts that require channel credentials fail fast.

YouTube Data API Shorts

  • Purpose: chunked uploads for generated Shorts from scripts/post-video-daily.ts and src/lib/youtube.ts.
  • Required secrets: YOUTUBE_CLIENT_ID, YOUTUBE_CLIENT_SECRET, YOUTUBE_REFRESH_TOKEN.
  • Bootstrap script: scripts/generate-youtube-token.ts.
  • Recovery: invalid_grant usually means the refresh token expired, was revoked, or was created in Google testing mode; regenerate the token after fixing OAuth consent settings.

TikTok

  • Purpose: TikTok Content Posting API upload-to-inbox for sandbox review, with production direct publishing only when the app and scopes support it.
  • Bootstrap script: scripts/generate-tiktok-token.ts.
  • Publishing path: scripts/post-video-daily.ts --platform tiktok uses src/lib/tiktok-client.ts; src/lib/tiktok-manual.ts remains the fallback when API credentials are absent.
  • Required secrets: TIKTOK_CLIENT_KEY, TIKTOK_CLIENT_SECRET, TIKTOK_REDIRECT_URI.
  • Token secrets: TIKTOK_REFRESH_TOKEN or TIKTOK_ACCESS_TOKEN.
  • Runtime variables: TIKTOK_ENV, TIKTOK_PRIVACY_LEVEL, TIKTOK_UPLOAD_CHUNK_SIZE_BYTES, TIKTOK_DISABLE_DUET, TIKTOK_DISABLE_COMMENT, TIKTOK_DISABLE_STITCH, TIKTOK_BRAND_CONTENT_TOGGLE, TIKTOK_BRAND_ORGANIC_TOGGLE, TIKTOK_IS_AIGC.
  • Diagnostics: scripts/check-tiktok-post-status.ts --publish-id <id> checks posting status; TIKTOK_LAST_PUBLISH_ID can supply the ID.
  • Scope rule: keep requested scopes to video.upload and user.info.basic unless direct publishing or read features are implemented and demonstrated.

5. Cloudflare Infrastructure & Storage

Cloudflare Pages

  • Purpose: static Next.js export hosting.
  • Deploy command: wrangler pages deploy out/ --project-name=tokenradar --branch=main --commit-dirty=true inside .github/workflows/deploy.yml.
  • Required secrets: CLOUDFLARE_API_TOKEN, CLOUDFLARE_ACCOUNT_ID.
  • Build gate: typecheck, lint, tests, static build, output verification, and file budget check run before deploy.

Cloudflare Web Analytics

  • Purpose: privacy-first RUM layer alongside GA4 and PageSpeed snapshots.
  • Preferred setup: dashboard injection from the Cloudflare Pages metrics page.
  • Manual setup: NEXT_PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN as a GitHub Actions variable.
  • Guardrail: do not enable dashboard injection and the manual token at the same time, or page views can be double-counted.

Cloudflare R2 Media Staging

  • Purpose: transient public media URLs for Meta and social video workflows.
  • Staging prefixes: video/YYYY-MM-DD/ and ig-carousel/YYYY-MM-DD/.
  • Cleanup: exact uploaded keys are deleted after successful Meta publishing; failed media is retained briefly for diagnostics and then removed by lifecycle rules or r2:cleanup-ledger.
  • Required secrets: R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET_NAME, R2_PUBLIC_URL.

Cloudflare R2 Persistent Video Assets

  • Purpose: shared b-roll library for short-form video generation.
  • Scripts: scripts/sync-video-assets-from-r2.ts, scripts/sync-video-assets-to-r2.ts, src/lib/video-asset-r2.ts.
  • Failure mode: missing R2 credentials keep local b-roll as fallback during hydration; publishing persistent assets to R2 requires credentials.

Cloudflare D1 Ops Ledger

  • Purpose: best-effort operational ledger for automation runs, social post tracking, R2 staging cleanup, and Cloudflare usage snapshots.
  • Scripts: scripts/d1-migrate.ts, scripts/d1-smoke.ts, scripts/record-automation-run.ts, scripts/backfill-social-ledger.ts, scripts/report-ops-ledger.ts, scripts/snapshot-cloudflare-usage.ts, scripts/cleanup-r2-staging.ts.
  • Required variables: CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN, D1_DATABASE_ID.
  • Alternate names: D1_API_TOKEN and CLOUDFLARE_D1_DATABASE_ID are accepted by src/lib/d1-client.ts.
  • Failure mode: most ledger steps use continue-on-error; social publishing continues when ledger writes fail.

6. Analytics, SEO & Performance Integrations

GA4 and Google Search Console

  • Purpose: engagement baseline export during daily refresh.
  • Script: scripts/export-engagement-baseline.ts.
  • Required values: GA4_PROPERTY_ID and GSC_SITE_URL or NEXT_PUBLIC_SITE_URL.
  • OAuth mode secrets: GOOGLE_OAUTH_CLIENT_ID, GOOGLE_OAUTH_CLIENT_SECRET, GOOGLE_OAUTH_REFRESH_TOKEN.
  • Service account option: GOOGLE_SERVICE_ACCOUNT_JSON when GOOGLE_AUTH_MODE=service_account.

PageSpeed Insights and Lighthouse

  • Purpose: performance snapshots and CI performance diagnostics.
  • Script: scripts/pagespeed-snapshot.ts; package script: npm run lighthouse:ci.
  • Required for PageSpeed snapshots: PAGESPEED_API_KEY.
  • Optional tuning: PAGESPEED_URL, PAGESPEED_STRATEGIES, PAGESPEED_MIN_PERFORMANCE, PAGESPEED_MIN_ACCESSIBILITY, PAGESPEED_MIN_BEST_PRACTICES, PAGESPEED_MIN_SEO.
  • Failure mode: scheduled PageSpeed job skips when PAGESPEED_API_KEY is absent.

IndexNow

  • Purpose: notify search engines after deploys.
  • Script: scripts/ping-indexnow.ts.
  • Required secret: INDEXNOW_KEY.
  • Required site value: NEXT_PUBLIC_SITE_URL or SITE_URL workflow variable.

7. Video Asset Provider Pipeline

Pexels and Pixabay

  • Purpose: provider b-roll refresh for the persistent video library.
  • Script: scripts/fetch-video-assets.ts.
  • Optional secrets: PEXELS_API_KEY, PIXABAY_API_KEY.
  • Optional selector: VIDEO_ASSET_PROVIDERS or --provider pexels,pixabay.

FFmpeg and Blender

  • Purpose: video processing and generated loop assets.
  • Workflow dependency: video-assets-refresh.yml and social video slots install FFmpeg on the runner.
  • Optional local variable: BLENDER_BIN or --blender <path> for scripts/generate-blender-assets.ts.
  • Failure mode: Blender generation can run with --optional, so the workflow can continue without local Blender availability.

8. Application and Build Variables

Next.js Public Configuration

  • Required build variable: NEXT_PUBLIC_SITE_URL; production should be https://tokenradar.co.
  • Optional public variables: NEXT_PUBLIC_SITE_NAME, NEXT_PUBLIC_GA_MEASUREMENT_ID, NEXT_PUBLIC_CLOUDFLARE_WEB_ANALYTICS_TOKEN, NEXT_PUBLIC_CONTACT_FORM_ENDPOINT.
  • Workflow variable aliases: SITE_URL and SITE_NAME feed production Actions jobs.
  • CSP note: if the contact form endpoint changes from Formspree, update public/_headers connect-src.

Build and Validation Controls

  • scripts/validate-env.ts treats NEXT_PUBLIC_SITE_URL as build-critical.
  • Functional generation/social variables are warned when missing: ANTHROPIC_API_KEY, COINGECKO_API_KEY, GEMINI_API_KEY, X OAuth credentials, Telegram broadcast credentials, and Telegram report credentials.
  • Optional deploy budget: CF_PAGES_FILE_BUDGET controls scripts/check-pages-file-budget.ts.
  • Optional content/build tuning: STATIC_CATEGORY_MIN_TOKENS can adjust category static output behavior.

9. Failure Handling, Diagnostics & Recovery

Notifications

  • GitHub workflows send failure alerts to Telegram when TELEGRAM_REPORT_BOT_TOKEN and TELEGRAM_REPORT_CHAT_ID are configured.
  • If reporting secrets are absent, workflows log a skip and do not fail solely because notifications cannot be sent.

Diagnostics Artifacts

  • Daily refresh, daily content generation, deploy, social automations, dependency security, performance, video asset refresh, and monthly snapshots upload failure diagnostics where configured.
  • Social automation caches data/posted and data/posted_video to preserve cooldown and duplicate-prevention state between runs.

Manual Recovery Paths

  • X: rerun scripts/generate-x-token.ts and update X_OAUTH2_REFRESH_TOKEN if rotating refresh-token persistence fails.
  • Meta: rerun scripts/refresh-meta-tokens.ts or complete manual app re-auth when tokens are invalid or expired.
  • YouTube: rerun scripts/generate-youtube-token.ts after fixing OAuth consent or revoked access.
  • TikTok: run scripts/check-tiktok-post-status.ts --publish-id <id> for diagnostics; fall back to src/lib/tiktok-manual.ts when API credentials are absent.
  • D1: run the d1-smoke manual social workflow option to verify insert/select/delete against the ops ledger.
  • R2 staging: confirm bucket lifecycle rules for video/ and ig-carousel/; run npm run r2:cleanup-ledger for tracked stale keys.

- Failure mode: most ledger steps use `continue-on-error`; social publishing continues when ledger writes fail.

## 9. Failure Handling, Diagnostics & Recovery

### Notifications
- GitHub workflows send failure alerts to Telegram when `TELEGRAM_REPORT_BOT_TOKEN` and `TELEGRAM_REPORT_CHAT_ID` are configured.
- If reporting secrets are absent, workflows log a skip and do not fail solely because notifications cannot be sent.

### Diagnostics Artifacts
- Daily refresh, daily content generation, deploy, social automations, dependency security, performance, video asset refresh, and monthly snapshots upload failure diagnostics where configured.
- Social automation caches `data/posted` and `data/posted_video` to preserve cooldown and duplicate-prevention state between runs.

### Manual Recovery Paths
- X: rerun `scripts/generate-x-token.ts` and update `X_OAUTH2_REFRESH_TOKEN` if rotating refresh-token persistence fails.
- Meta: rerun `scripts/refresh-meta-tokens.ts` or complete manual app re-auth when tokens are invalid or expired.
- YouTube: rerun `scripts/generate-youtube-token.ts` after fixing OAuth consent or revoked access.
- TikTok: run `scripts/check-tiktok-post-status.ts --publish-id <id>` for diagnostics; fall back to `src/lib/tiktok-manual.ts` when API credentials are absent.
- D1: run the `d1-smoke` manual social workflow option to verify insert/select/delete against the ops ledger.
- R2 staging: confirm bucket lifecycle rules for `video/` and `ig-carousel/`; run `npm run r2:cleanup-ledger` for tracked stale keys.
