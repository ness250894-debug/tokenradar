TokenRadar Testing Flow Contract

This document defines the testing and validation flow for TokenRadar. The maintained source of record is the artifact pair in docs/testing/; the legacy root TESTING.md source file is retired.

1. Test Framework

  • Unit and integration-style tests run on Vitest.
  • Configuration lives in vitest.config.ts with Node environment, globals enabled, and tests/**/*.test.ts included.
  • Local commands:

- npm run test runs the suite once. - npm run test:watch runs Vitest in watch mode.

  • Vitest coverage is configured with the V8 provider and text/lcov reporters, but there is no package-level coverage script or threshold gate yet.

2. Current Test Inventory

The repository currently has 62 Vitest files under tests/. Coverage is broader than the original testing note and includes:

  • Core scoring and data logic: metrics, config, formatters, schemas, market data quality, fetch retry behavior, token selection, token icons, directory filters, and watchlist storage.
  • Content and SEO quality: article formatting and repair, content loading, content quality, markdown rendering, validation scripts, SEO helpers, SEO contract implementation, search intent, prompt contract, security headers, and quality-check CLI behavior.
  • Social and publishing systems: X, Telegram, Meta, TikTok, social editorial policy, link policy, history, variety, social ledger backfill, post routing, reporters, partners, and ops ledger behavior.
  • Cloudflare and storage clients: D1 client behavior, D1 ops ledger helpers, R2 client behavior, video asset R2 keys, and asset pruning.
  • Video and media generation: audio config, b-roll overlay logic, Blender asset planning, video assets, video formats, and video recipes.
  • Automation docs and observability: workflow notification/diagnostic contracts and engagement baseline summaries.

3. Required Local Validation

For code or flow changes that can affect production, the local validation baseline should mirror deploy CI:

  1. npx tsc --noEmit for type checking.
  2. npm run lint for ESLint.
  3. npm run test for the Vitest suite.
  4. npm run build for the full static export pipeline.
  5. npm run deploy:check-files after a build when static output size or Cloudflare Pages budget may be affected.

Small documentation-only edits may use a narrower check, but artifact edits should at least regenerate/check the relevant artifact pair.

4. CI and Release Gates

The deploy workflow runs typecheck, lint, tests, static export build, output verification, Cloudflare Pages deploy, and IndexNow ping when configured.

The production build starts with prebuild, which runs environment validation, search-intent computation, data consolidation, content validation, OG image generation, and sitemap generation before next build.

Performance and security are separate scheduled gates:

  • performance.yml runs Lighthouse CI against the static export and PageSpeed Insights against production when the API key is present.
  • dependency-security.yml runs npm run audit:prod for high-severity production dependency issues.

5. Content and Data Pipeline Gates

Daily content generation is part of the testing flow because it can publish user-facing pages without a developer manually running deploy checks. Its gates are:

  1. Generate queued drip content.
  2. Run scripts/quality-check.ts --dir data/queue --fix --delete-failures.
  3. Publish approved queue entries with live data hydration.
  4. Inject internal links.
  5. Repair article formatting.
  6. Run scripts/validate-content.ts.
  7. Run npm run build before committing and dispatching deploy.

Daily refresh validates refreshed artifacts by consolidating data, validating content, and regenerating sitemaps after CoinGecko, TGE, reference article, metrics, Meta token, and OG image updates.

6. Social, Storage, and Smoke Flows

Social automation tests rely mostly on mocked clients in Vitest, but the scheduled workflow also includes operational checks:

  • D1 migrations, run recording, R2 cleanup, social ledger backfill, and usage snapshots are best-effort preflight steps.
  • scripts/d1-smoke.ts is the explicit live D1 insert/select/delete smoke test and should be treated as an integration smoke, not a unit test.
  • Platform posting scripts for Telegram, X, Instagram, Threads, TikTok, and short-form video require mocked unit coverage plus careful manual or workflow-dispatch validation before changing payloads, secrets, media upload behavior, or rate-limit handling.

7. Mocking and Network Policy

Vitest tests should not make live network calls by default. External APIs such as CoinGecko, X, Telegram, Meta, TikTok, Gemini, Cloudflare D1, and R2 should be mocked with vi.mock(), vi.spyOn(globalThis, "fetch"), SDK mocks, or fixture files.

Live checks are allowed only when they are explicit smoke or workflow-dispatch operations with required secrets, clear blast radius, and no dependency on the normal npm run test path. vitest.config.ts installs tests/setup/no-network.ts, so unmocked fetch calls fail fast and new tests must explicitly stub or spy on network clients.

8. Browser and Static Export QA

There is no dedicated Playwright or browser E2E suite. UI or route changes should be validated through the static export when relevant:

  • Run npm run build and inspect representative pages in out/.
  • Run npm run seo:qa for representative SEO metadata, canonical, sitemap, robots, OG image, Twitter card, JSON-LD, and internal-link checks.
  • Use Lighthouse/PageSpeed workflows for performance regressions on scheduled or manual runs.

9. Maintenance Controls

  • docs/testing/testing.json and docs/testing/testing.html are the maintained testing documentation artifacts.
  • npm run docs:testing regenerates the JSON and HTML artifact pair from the rawMarkdown stored in docs/testing/testing.json.
  • Check drift with npx tsx scripts/generate-doc-artifacts.ts --doc testing --check.
  • Keep the test inventory, CI gates, smoke-test exceptions, and artifact maintenance instructions synchronized when workflows, scripts, or test files change.
