TokenRadar SEO Flow Contract

This document defines the SEO, metadata, crawlability, and post-deploy discovery flow for TokenRadar. The maintained source of record is now the generated artifact pair in docs/seo/; the legacy SEO.md source file has been retired.

1. Static Export Model

  • TokenRadar ships as a pure Next.js static export with output: "export" in next.config.ts.
  • There is no server runtime that can fix metadata, robots rules, or canonical URLs after a request arrives.
  • SEO-critical data must exist before next build renders HTML into out/ for Cloudflare Pages.
  • NEXT_PUBLIC_SITE_URL is normalized through src/lib/seo.ts and drives metadataBase, sitemap locations, canonical helpers, robots output, and absolute schema URLs.

2. Build-Time Data Pipeline

The production npm run build flow starts with prebuild and must be treated as part of SEO, not just deployment plumbing:

  1. scripts/validate-env.ts checks required public build settings.
  2. scripts/compute-search-intent.ts refreshes the free-data intent layer and history snapshots.
  3. npm run consolidate runs scripts/consolidate-data.ts, builds optimized data blobs, and copies browser-safe data into public/data/.
  4. scripts/validate-content.ts validates JSON, schemas, generated article integrity, TGE consistency, outbound URLs, placeholders, and conflict markers.
  5. scripts/generate-og-images.tsx creates static token OG images and the daily movers image when missing or when run with --force.
  6. scripts/generate-sitemap.ts writes public/sitemap.xml, public/sitemap-main.xml, and public/sitemap-tokens.xml.

3. Content Generation and Publication Flow

The daily content workflow is part of the SEO lifecycle:

  1. scripts/generate-content.ts --drip --queue creates bounded draft article JSON in data/queue/ using the smart priority queue.
  2. scripts/quality-check.ts --dir data/queue --fix --delete-failures applies the queue quality gate before anything can publish.
  3. scripts/publish-from-queue.ts hydrates live placeholders, rejects unresolved live data, writes approved articles into content/tokens/, and records quality snapshots.
  4. scripts/inject-internal-links.ts adds semantic internal links to recently modified articles.
  5. scripts/repair-article-content.ts normalizes published formatting.
  6. scripts/validate-content.ts re-checks published content before the workflow commits and dispatches deploy.

4. Metadata, Canonicals, and Robots

  • Global fallback metadata lives in src/app/layout.tsx: title template, description, keywords, metadataBase, manifest, icons, Open Graph, Twitter Card, and default robots.
  • src/lib/share-metadata.ts provides shared default Open Graph and Twitter image metadata for static, category, search intent, and TGE surfaces that override page-specific social copy.
  • Dynamic page metadata is built with generateMetadata() for token routes, upcoming TGE routes, category pages, search intent pages, learn pages, and static guides where needed.
  • Token overview pages set robots: noindex, follow when the overview article fails indexability; article subpages return 404 when their required article is not indexable.
  • Canonicals should be self-referential for indexable static routes. Released /upcoming/[token] pages canonicalize to the main token route when a tracked token page exists.
  • src/app/robots.ts and public/robots.txt both exist; keep them synchronized or explicitly designate one source of truth before changing bot policy.

5. Indexability and Quality Gates

  • isTokenOverviewIndexable() requires market volume above TOKEN_OVERVIEW_MIN_VOLUME_USD, an overview article, a passing article quality result, and at least TOKEN_OVERVIEW_MIN_WORDS.
  • isArticleIndexable() requires evaluateArticleQuality() to pass for generated price-prediction, how-to-buy, and TGE preview content.
  • Blocking article failures include too few words, missing early summary table, missing FAQ, missing disclaimer, too few numeric data points, repeated filler, malformed tables, prohibited phrases, invalid schemas, unapproved outbound URLs, and unresolved live placeholders.
  • Warnings such as borderline length, long sentences, unsupported heading depth, weak opening summaries, missing continuation links, hardcoded live-date phrasing, and nonstandard disclaimer text require review for high-risk or high-traffic pages.

6. Sitemap Coverage

  • sitemap-main.xml includes the homepage, directories, category pages, search intent pages, upcoming TGE pages with previews that do not canonicalize to live token profiles, learn glossary pages, static money pages, and legal/support pages.
  • sitemap-tokens.xml includes only indexable token overview pages, indexable price-prediction and how-to-buy articles, and verified pilot transfer-to-ledger guides.
  • sitemap.xml is a sitemap index pointing crawlers to the generated chunks.
  • lastmod values come from source dates, git dates, generated article dates, token fetch dates, or stable fallbacks depending on the surface.
  • Non-indexable pages may still render for users when appropriate, but they must not be added to sitemap chunks.

7. URL Inventory

Current SEO surfaces include:

  • Core: /, /tokens, /about, /contact, /privacy, /terms, /disclaimer.
  • Token hubs: /[token], /[token]/price-prediction, /[token]/how-to-buy, /[token]/transfer-to-ledger.
  • Discovery hubs: /category/[category], /search-intent, /search-intent/[intent], /upcoming, /upcoming/[token].
  • Education and trust: /learn, /learn/[slug], /best-crypto-hardware-wallets, /crypto-tax-guide.
  • Private or utility surfaces such as /analytics/local, /watchlist, /offline, and callback pages should remain noindex or out of the sitemap unless their role changes.

8. Structured Data and Rich Results

  • Global JSON-LD in the root layout defines WebSite, Organization, and founder Person entities.
  • Token overview and price-prediction pages emit Article and BreadcrumbList JSON-LD when content is rendered.
  • How-to-buy and transfer-to-ledger pages emit HowTo; how-to-buy also emits ExchangeRateSpecification.
  • Learn and static guide pages emit Article, BreadcrumbList, and, where relevant, list-style structured data.
  • Schema URLs, image URLs, publisher logos, dates, authors, and page canonicals must stay consistent with rendered metadata and sitemap entries.

9. Open Graph and Social Images

  • Static social images are rendered by scripts/generate-og-images.tsx through src/lib/og-renderer.ts and written to public/og/token/.
  • Existing token images are skipped unless the script runs with --force; use force when market data, template design, or token image policy changes.
  • public/og/movers.png is generated separately from selected daily movers and is also skipped unless missing or forced.
  • Social platforms cache OG images aggressively, so refreshing an existing image requires regenerating the asset, redeploying it, and validating with platform debuggers when important.

10. Internal Linking and Crawl Depth

  • scripts/inject-internal-links.ts adds bounded token and learn links to recently modified article JSON before deployment.
  • src/lib/markdown.ts also validates internal links, unwraps unsafe or nonexistent routes, and programmatically links eligible token names at render time.
  • Internal links should point only to routable, indexable, or intentionally useful surfaces; ambiguous token names and dead generated paths must be unwrapped rather than shipped.
  • Category links, related token cards, research actions, and article completion actions are part of crawl depth and should be checked when route inventory changes.

11. Post-Deploy Discovery and Monitoring

  • The deploy workflow runs typecheck, tests, static export, output verification, Cloudflare Pages deploy, and IndexNow ping where configured.
  • scripts/ping-indexnow.ts expands public/sitemap.xml when it is a sitemap index and submits the page URLs found in child sitemap chunks.
  • .github/workflows/performance.yml runs Lighthouse CI against the static export and PageSpeed Insights against production when the API key is configured.
  • scripts/export-engagement-baseline.ts exports GA4 landing pages, tracked events, and Google Search Console page-query-device rows for 28 and 90 day baselines.
  • Search Console coverage, sitemap processing, canonical selection, impressions, CTR, page speed, and high-value query drift are part of the SEO feedback loop.

12. Maintenance Controls

  • docs/seo/seo.json and docs/seo/seo.html are unignored and serve as the maintained source of record now that SEO.md is retired.
  • npm run docs:seo regenerates the JSON and HTML artifact pair from the rawMarkdown stored in docs/seo/seo.json.
  • npm run seo:verify checks SEO doc artifact stats, shared robots policy synchronization, and IndexNow page URL expansion.
  • npm run seo:qa audits representative rendered static-export pages for title, description, canonical, robots, OG image, Twitter card, JSON-LD, sitemap membership, and internal links.
  • scripts/ping-indexnow.ts expands sitemap index chunks before submitting page URLs to IndexNow.
