TokenRadar Video B-roll

This folder holds optional local media layers for Remotion videos and the local mirror of the persistent R2 b-roll library.

Local asset generation

Generate or extend the local manifest from provider clips:

npm run video:assets -- --max 6

Provider keys are optional per provider. Configure PEXELS_API_KEY and/or PIXABAY_API_KEY; use VIDEO_ASSET_PROVIDERS or --provider pexels,pixabay to choose sources. Useful fetch options include --query, --max, and --dry-run.

FFmpeg/ffprobe must be available for downloaded clips because metadata, size, and SHA-256 are probed before publish. Set FFPROBE_BIN if ffprobe is not on PATH.

Blender loops

Generate local Blender motion loops with:

npm run video:blender -- --preset all

Blender generation is local and optional. It requires Blender on PATH, BLENDER_BIN, or --blender <path>. Useful options include --optional, --force, --seconds, --fps, --width, and --height.

Useful presets:

  • radar_grid
  • terminal_scan
  • liquidity_depth
  • orbital_map

R2 sync and CI flow

The persistent library lives in Cloudflare R2 under video-assets/broll/. Use these commands around local generation:

npm run video:assets:pull -- --manifest-only
npm run video:assets:pull
npm run video:assets:push

R2 sync requires R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET_NAME, and R2_PUBLIC_URL. Upload publishes MP4 assets first, then a versioned manifest, then video-assets/broll/manifest.json.

.github/workflows/video-assets-refresh.yml runs the scheduled refresh: hydrate the current R2 manifest, fetch provider clips, generate optional Blender loops, and publish back to R2. .github/workflows/social-automations.yml hydrates the manifest before scripts/post-video-daily.ts renders short-form video.

Manifest contract

The local manifest is public/video-assets/broll/manifest.json; local asset sources should be safe relative paths such as broll/example.mp4. public/video-assets/broll/manifest.example.json shows the minimum shape for manual or generated entries.

Publishable R2 assets need source: "local", duration, width, height, file size, and sha256. Stock-provider assets also need sourcePageUrl and attribution so license audits and future pruning can trace the source.

scripts/post-video-daily.ts reads the manifest, selects a shot list per platform, and hydrates missing selected local files from R2 when credentials are available. If the manifest is missing, empty, invalid, or selected files cannot be hydrated, the renderer falls back to generated motion backgrounds.

Budget pruning

Use npm run video:assets:prune -- --delete-local after fetch/Blender generation to remove missing, checksum-mismatched, or over-budget local assets from the manifest. After publishing the retained manifest, use npm run video:assets:prune -- --r2-only --delete-r2-unreferenced to delete R2 b-roll media objects no longer referenced by the current manifest.

The weekly video-assets-refresh.yml job hydrates the full R2 library, fetches provider clips, refreshes Blender loops, prunes the budget, publishes retained assets and manifest, then deletes unreferenced R2 media. Failed refresh runs upload diagnostics from public/video-assets/broll/ and send Telegram alerts when report secrets are configured. Keep API keys and R2 credentials in GitHub Actions secrets or local environment variables; never commit them in manifests or docs.
